# wireflow 0.3 — 저니 보드 보기와 코드 재구성

## 왜

- wireflow는 기획 초기 팀 방향 맞추기와 개발 인계 자료를 한 파일로 만드는 도구여야 한다.
- 0.2의 레인 순서도는 실제 사용(학원2.0 실험, 노드 19개)에서 읽을 수 없었다.
  - 4개 레인을 오가는 곡선이 엉켰다.
  - '맞춤' 상태에서 글자가 보이지 않았다.
  - 예외 노드가 기본 경로 사이에 섞였다.
- 같은 데이터를 손으로 그린 저니 보드는 잘 읽혔다. 참고 파일:
  - `nalgae/docs/wireflow/hakwon2-first-experiment/journey-board.html`
  - `libera-susi-consulting/main/docs/user-journey/유저저니_보드_리포트단독_PLG_2.html`
- 사용자는 0.2 코드가 지저분하다고 봤다.
  - `viewer/app.js` 648줄이 한 클로저에 들어 있다.
  - 빌드는 정규식으로 `import`/`export`를 지운다.
- 이번 작업의 최우선 기준은 **가독성**이다. 컴포넌트 단위로 분리하고 lint·format을 적용한다.

## 목표

1. 개요 화면을 **저니 보드**로 교체한다. 레인 순서도는 제거한다.
2. 노드에 칩을 붙인다: 상태, 지표, 실험 변수, 알림, 예외 코드.
3. 기본 경로를 강조하고, 쓰지 않는 분기는 흐리게 그린다.
4. **로그 리스트 탭**을 추가한다: 이벤트 표와 공통 속성.
5. `check`에 이벤트·예외 검사를 추가한다.
6. 소스를 기능별 모듈로 나누고, Biome lint/format과 esbuild 번들을 쓴다.
7. 0.2 파일(`view: "flowchart"`)은 그대로 열려야 한다.

## 비목표

- 노드 여러 개를 카드 하나로 합치기. 손으로 그린 보드의 "04–05"가 그런 예다. 노드 하나는 카드 하나다.
- 좌표를 손으로 지정하기. 배치는 항상 자동이다.
- 와이어프레임 보기의 화면 안쪽 블록 디자인을 바꾸기. 배치·코드 구조만 정리한다.
- TypeScript로 바꾸기. JSDoc 타입 검사는 후속 작업이다.

## 반목표 (이렇게 되면 실패)

- 노드 20개 안팎의 보드에서 '전체 보기' 상태로 카드 제목을 읽을 수 없다.
- 선이 카드를 관통하거나, 다른 열을 대각선으로 가로지른다.
- 모듈을 나눴지만 상태를 여러 곳에서 직접 바꿔서, 어디서 화면이 갱신되는지 따라갈 수 없다.
- 플러그인 사용자가 `wireflow build`를 하려고 npm 설치를 해야 한다.

## 접근 (검토한 것과 선택)

| 안 | 내용 | 판단 |
|---|---|---|
| **A. wireflow 개요를 보드로 교체** | 같은 flow JSON으로 보드, 와이어프레임, 직접 걸어보기, `check`, 이벤트 표를 만든다. | **선택.** 인계 자료에는 검증과 이벤트 표가 같은 데이터에서 나와야 한다. 0.2에서 드러난 문제는 그리는 방식이었고, 엔진은 쓸 만했다. |
| B. 독립 `journey-board` 플러그인 | 저니 보드 전용 JSON과 뷰어를 둔다. | 같은 서비스를 두 번 기술하게 되고, 경로 검증을 다시 만들어야 한다. |
| C. wireflow 엔진을 공유하는 별도 플러그인 | 다른 플러그인의 스크립트를 가져다 쓴다. | 플러그인은 따로 설치되므로, 다른 플러그인에 의존하면 설치 상태에 따라 깨진다. |

## 데이터 모델 추가 (flow JSON)

필드는 모두 선택 사항이다. 0.2 파일은 그대로 유효하다.

### 흐름 수준

```jsonc
{
  "view": "board",                // "board" | "wireframe"; 생략 시 0.2처럼 "wireframe"; 0.2의 "flowchart"는 "board"로 읽는다
  "actors": ["학부모", {"name": "학생", "color": "#B4791F"}],   // 문자열 또는 {name, color}
  "primary": "book",              // 시나리오 id; 그 시나리오가 지나는 노드·전이가 기본 경로
  "eventProps": [                 // 모든 이벤트 공통 속성 (로그 탭 1번 표)
    {"name": "household_id", "use": "형제자매·중복 신청 묶기"}
  ],
  "events": [
    {"id": "landing_view", "type": "normal", "at": ["landing", "landing-b"], "props": ["message_variant"], "note": "랜딩 진입"},
    {"id": "apply_submitted", "type": "normal", "at": "landing.apply"},
    {"id": "trial_absent", "type": "drop", "at": "absent"}
  ]
}
```

- `events[].type`은 `normal`(정상), `drop`(이탈), `error`(에러) 중 하나다.
- `events[].at`은 노드 id 또는 `노드id.액션id`(전이)다. 하나의 문자열이거나, 같은 이벤트가 여러 곳에서 나면 문자열 배열이다.
  - 이벤트 id는 유일하다.
  - 로그 탭은 이벤트 하나를 한 행으로 보여주고, 발생 위치는 모두 나열한다.
  - 액션 id를 이벤트로 자동 간주하지 않는다. 이벤트는 저자가 명시한다.
- `view`의 기본값이 `wireframe`인 이유: 0.2 파일 대부분이 `view`를 생략한 와이어프레임 파일이기 때문이다. `wireflow:start`는 새 파일에 `view`를 항상 명시한다.

### 노드 수준

```jsonc
{
  "state": "PAID",                         // 상태값 칩 (mono)
  "metrics": ["결제전환율"],                 // 지표 칩
  "experiments": ["가격", "메시지 ①/②"],     // 실험 변수 칩
  "notify": ["결제 성공 알림톡"],            // 발송 알림 칩
  "exception": "E02",                      // 이 노드가 예외 노드임을 표시하는 코드; 예외 띠에 배치
  "dormant": true                          // 문만 열어둔 분기: 흐리게, 기본 경로에서 제외
}
```

- 예외 노드를 가리키는 전이가 있으면, 출발 노드에 그 예외 코드 칩이 자동으로 붙는다. 저자가 직접 적지 않는다.
- 미정 결정은 0.2의 노드별 `decisions`를 그대로 쓴다. 보드는 이를 단계별로 모아 결정 띠에 카드로 보여준다.

## `check` 추가 항목

| 코드 | 심각도 | 조건 |
|---|---|---|
| `broken-event` | 🔴 | `events[].at`이 없는 노드나 전이를 가리킨다 |
| `unknown-primary` | 🔴 | `primary`가 없는 시나리오 id다 |
| `orphan-exception` | 🟡 | `exception` 노드로 들어오는 전이가 없다 |
| `untracked-step` | 🔵 | `events`가 하나라도 있는데, 기본 경로의 한 걸음(전이 + 도착 노드)에 이벤트가 하나도 없다. 전이나 도착 노드 중 하나에만 있으면 추적된 것으로 본다. 진입 노드 자체도 한 걸음으로 센다. |

- 종료 코드 규칙은 0.2와 같다.
- `validate`는 다음을 검사한다:
  - `events[].type`이 정해진 값인지
  - 이벤트 id가 중복되지 않는지
  - `exception` 코드가 중복되지 않는지
  - `actors` 객체의 `color`가 `#RRGGBB` 형식인지

## 보드 배치 규칙 (순수 함수, 단위 테스트 대상)

1. **열.** 큰 열은 `stages`다. 한 단계 안에서는 노드를 그래프 깊이 순서로 세부 열에 놓는다.
   - 그래프 깊이는 진입점(`start`, `entries`)에서 DFS로 뒤로 가는 간선을 제거한 뒤 구한 최장 경로 순위다.
   - 세부 열 번호 = 순위 − 그 단계의 최소 순위.
2. **행.**
   - 기본 경로 노드는 가운데 **척추선**에 놓인다.
   - 한 세부 열에 기본 경로가 지나는 노드가 둘 이상이면(예: 교과·탐구를 오가는 경로), 그 열에서는 아무 노드도 척추선에 놓지 않고 묶음 전체를 척추선 중앙에 맞춘다.
   - 같은 세부 열의 나머지 일반 노드는 척추선 위·아래로 번갈아 쌓인다(위 먼저). 기본 경로 노드가 없는 세부 열은 쌓은 묶음을 척추선 중앙에 맞춘다.
   - `primary`가 없으면 각 세부 열의 첫 노드(`screens` 순서)를 척추선에 놓는다.
3. **띠.** 일반 노드 영역 아래에 띠 두 개가 있다.
   - **예외 띠**: `exception` 노드의 x는 그 노드로 들어오는 전이의 출발 노드 중 첫 번째(기본 경로 순서, 그다음 `screens` 순서)의 세부 열 x다. 자기 `stage`와 무관하다.
     - 들어오는 전이가 없으면 자기 단계의 첫 세부 열에 둔다.
     - 같은 x에 둘 이상 겹치면 오른쪽으로 한 칸(카드 너비 + 세부 열 간격)씩 민다.
   - **결정 띠**: 단계별 미정 결정 카드를 둔다.
   - 띠에는 제목("이탈했을 때 확인할 일", "미정 결정")과 옅은 배경이 있다.
4. **카드 크기.** 너비는 고정 220px이다. 높이는 내용(제목 2줄, 본문 2줄, 칩 줄 수)에 따라 정해진다.
   - 배치 단계에서는 칩 수와 글자 수로 높이를 추정한다(순수 함수).
   - DOM 측정은 하지 않는다. 결과가 결정적이어야 하기 때문이다.
5. **간격.** 세부 열 사이는 48px, 단계 사이는 72px이다. 단계 헤더는 열 위에 적는다.
6. **선 (직교 경로).**
   - **앞으로 가는 전이**: 출발 카드 오른쪽 가운데 → 두 열 사이 통로의 x까지 수평 → 수직 → 도착 카드 왼쪽 가운데로 수평.
     - 같은 통로를 여러 선이 쓰면 x를 6px씩 어긋나게 한다.
   - **뒤로 가는 전이**와 같은 열 안의 전이: 출발 카드 위(또는 아래) → 일반 노드 영역 바깥의 우회로 → 도착 카드 위(또는 아래). 위로 돌지 아래로 돌지는 두 카드의 평균 위치로 정한다.
   - **열을 건너뛰는 앞 전이**: 출발 카드와 도착 카드 사이 수평 구간이 중간 세부 열의 카드와 겹치지 않으면 위 규칙대로 그린다. 겹치면 뒤로 가는 전이처럼 일반 영역 바깥 우회로(위 또는 아래)를 쓴다. 장애물 검사는 "수평 구간이 지나는 열의 카드 박스와 교차하는가"만 본다. 일반적인 경로 탐색은 하지 않는다.
   - **예외로 가는 전이**: 출발 카드 아래 가운데에서 시작한다. 바로 아래 같은 열에 다른 카드가 없으면 수직으로 내려간다. 있으면 출발 카드 오른쪽 통로로 빠져서 내려간 뒤 수평으로 예외 카드 위에 닿는다. 빨간 점선으로 그린다.
   - **예외 노드에서 나가는 전이**(예: 재안내 후 신청 안내로 복귀): 예외 카드 위에서 시작해 오른쪽 통로로 올라가는 회색 점선으로 그린다.
   - **선 라벨**:
     - 분기(`decision`) 노드에서 나가는 선에만 액션 라벨을 붙인다.
     - 나머지 선은 마우스를 올렸을 때 툴팁으로 보여준다.
   - **강조**: 기본 경로 선은 진하게, `dormant` 노드에 닿는 선은 흐리게 그린다.
7. **출력.** `{ nodes: Map<id, box>, bands: [...], stageHeaders: [...], edges: [{id, d, kind, label?, labelAt?}], size }`
   - 렌더러는 이 결과만 그린다.

## 화면 구성

```
┌ 제목 · 목표 ─────────── [보드][와이어프레임][로그 리스트][검토 ●2] ─ 경로▾ 직접걸어보기 수정요청 3 ┐
│ 범례: ● 학부모 ● 학생 ● 운영 ● 시스템 ● 예외   ─ 기본경로   ┄ 예외   ▢ 흐림=문만 열어둠     │
├──────────────────────────────────────────────────────────────────────────────┤
│  (캔버스 전체 폭: 드래그·휠·맞춤·단계로 이동)                         [노드 상세 패널 ▸] │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **탭**: 보드 / 와이어프레임 / 로그 리스트 / 검토. 검토 탭 옆 숫자는 발견 사항 수다.
  - 0.2의 상시 사이드바는 없앤다.
  - 로그 리스트와 검토는 캔버스 대신 문서처럼 읽히는 페이지로 보여준다.
- **노드 클릭**: 오른쪽에 접히는 상세 패널이 열린다. 패널 내용:
  - 기획 근거, 조건·분기, 연결, 칩 전체
  - 이 노드에 걸린 이벤트
  - 수정 요청 입력
- **직접 걸어보기, 수정 요청, 제안 토글**: 0.2 동작을 유지한다.
- **보드 카드 구성**: 위에서부터 다음 순서다.
  - 행위자 태그(색)와 번호
  - 제목
  - 본문 2줄(넘치면 말줄임)
  - 칩 줄: 상태, 지표, 실험, 알림, 예외 코드
  - 출처 표시(AI 추정 등)는 0.2처럼 카드 테두리 스타일과 작은 배지로 보여준다.

## 코드 구조

```
plugins/wireflow/
  package.json              # devDependencies: @biomejs/biome, esbuild (개발 전용)
  biome.json
  scripts/
    wireflow.mjs            # CLI: check / build / example (Node 내장 모듈만 사용)
    lib/                    # 모델 (Node·브라우저 공용, 순수 함수)
      validate.mjs
      scenario.mjs          # applyAction, enabledActions, runScenario
      proposals.mjs
      graph.mjs             # 도달성, 갇힘, 깊이(rank) 계산
      check.mjs             # 발견 사항 조립, exitCode
      messages.mjs          # ko/en 발견 사항 문구
      constants.mjs         # DEVICES, KINDS, VIEWS, EVENT_TYPES
    viewer/
      src/
        main.mjs            # 부팅: store 생성, 컴포넌트 마운트
        store.mjs           # 단일 상태 + dispatch(action) + subscribe; 상태 변경은 여기서만
        html.mjs            # html`` 태그 (자동 이스케이프)
        i18n.mjs
        layout/
          board.mjs         # 위 배치 규칙
          wireframe.mjs     # 0.2 단계 행 배치 정리본
          routes.mjs        # 직교 선 경로
        components/
          toolbar.mjs  tabs.mjs  legend.mjs
          canvas.mjs   camera.mjs  edges.mjs
          board-card.mjs  frame-node.mjs  chips.mjs
          node-panel.mjs  review-page.mjs  log-page.mjs
          player.mjs  requests.mjs
        styles/             # 컴포넌트별 CSS 파일, 빌드 시 연결
      dist/viewer.js        # esbuild 번들 (커밋됨; 런타임 build는 이 파일을 인라인)
      dist/viewer.css
      viewer.html
    test/
      *.test.mjs
```

- **런타임 빌드는 지금처럼 의존성이 없다.**
  - `wireflow build`는 `dist/viewer.js`, `dist/viewer.css`, flow 데이터를 `viewer.html`에 끼워 넣는다.
  - 정규식으로 import를 지우는 방식은 없앤다.
- **개발 명령**: `npm run lint`(biome check), `npm run format`, `npm run bundle`(esbuild → dist), `npm test`(node --test).
- **CI** (`wireflow-model` job):
  1. `npm ci`
  2. lint
  3. test
  4. bundle 후 `git diff --exit-code scripts/viewer/dist`: 커밋된 번들이 소스와 같은지 확인
  5. 예제 check·build
- **컴포넌트 규약**:
  - 각 컴포넌트는 `render(state) → Html` 또는 `mount(el, store)` 하나만 내보낸다.
  - 이벤트 처리는 `store.dispatch({type, ...})`로만 한다.
  - DOM을 직접 바꾸는 곳은 `canvas`, `camera` 정도로 한정한다.
- **lint 규칙**: Biome 추천 규칙에 더해 다음을 지킨다.
  - 줄 길이 100
  - 파일당 300줄 안팎을 넘기면 분리를 고려한다(규칙이 아니라 리뷰 기준).
