# Troubleshooting

| 증상 | 원인·해결 |
|---|---|
| `check`가 exit 2 | JSON 문법 또는 모델 오류(중복 id, 없는 start, stage 범위, `actions` 누락, 제안 충돌). 메시지의 id를 고친다. |
| 의도한 화면이 `unreachable` | 어떤 버튼도 그 화면을 가리키지 않음. 딥링크 진입이면 `entries`에 추가. |
| 오류 화면이 `trapped` | 처음/종료로 돌아갈 버튼이 없음. 현재 구현 재현이라면 의도된 결과 — proposal로 해결안을 둔다. |
| 시나리오가 `조건 … 불충족` | `when` 값과 앞 단계의 `set`/시나리오 `vars`가 정확히 일치해야 한다(문자열 공백 포함). |
| 재빌드 후 수정 요청 목록이 사라짐 | 요청은 브라우저 localStorage에 flow `id` + HTML 파일명으로 저장된다. 둘 중 하나가 바뀌었거나 다른 브라우저/프로필. |
| 뷰어 화면이 너무 작음 | **전체 보기**는 전체 맞춤이라 노드가 많으면 작다. **단계로 이동**으로 한 단계에 맞추거나, ⌘/Ctrl+휠로 줌, 드래그로 이동. |
| 보드에서 노드가 척추선에 안 놓임 | `primary`가 없거나 그 시나리오가 중간에 실패했다. 실패 전까지 지난 노드만 기본 경로가 된다. `check`의 `scenario-failed`·`unknown-primary`를 먼저 고친다. |
| `orphan-exception` | 예외 노드로 가는 버튼이 없다. 이탈이 일어나는 노드에 그 예외로 가는 action을 둔다. |
| `untracked-step` | 기본 경로의 한 걸음(전이나 도착 노드)에 이벤트가 없다. 로그가 필요 없는 걸음이면 그대로 두어도 된다(🔵). |
| 0.2 파일이 와이어프레임으로 열림 | `view`가 없으면 와이어프레임이다. 보드로 열려면 `"view": "board"`를 적는다. |
| 복사 버튼이 동작 안 함 | `file://`에서 클립보드 권한이 막힌 브라우저. 대체 방식(execCommand)으로 재시도하며, 안 되면 패널 내용을 직접 선택해 복사. |
| HTML을 만들 수 없음 (Node 없음) | flow JSON만 전달하고 로컬에서 `node wireflow.mjs build` 실행을 안내. |
